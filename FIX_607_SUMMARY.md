# Fix for Issue #607: Repeated Reprocessing of the Entire Context

## Problem Statement
The agent was repeatedly rebuilding and reprocessing the entire system prompt on every turn, causing the model to reprocess thousands of tokens unnecessarily. This was inefficient and contradicted the principle maintained in ZeroClaw, which only updates the latter parts of the prompt while keeping the system prompt intact.

### Original Symptoms
- Context was repeatedly changed and reprocessed in every turn
- System prompt constantly switched between different contexts (reasoning, chat, summary)
- Excessive token reprocessing (3000+ tokens per turn)
- Non-deterministic token counts between iterations

## Root Causes Identified

### 1. **No System Prompt Caching**
The `BuildSystemPrompt()` function was called on every message and completely rebuilt the system prompt from scratch by:
- Reading bootstrap files from disk
- Loading skills summary
- Loading memory context
- Rebuilding the entire context structure

This meant the same system prompt was being rebuilt and reprocessed with every user message, even if nothing had changed.

### 2. **Flawed ForceCompression Logic**
The `forceCompression()` function had a critical bug:
- It assumed `history[0]` was a system prompt, but session history never contains system prompts
- It tried to append a compression note to `history[0]` (the first conversation message)
- This corrupted the conversation history and changed the system prompt structure on each compression

## Solution Implemented

### 1. System Prompt Caching (pkg/agent/context.go)

**Added caching fields to ContextBuilder:**
```go
systemPromptCache   string              // Cached system prompt
systemPromptTime    time.Time           // When the cache was created
systemPromptCacheMu sync.RWMutex        // Thread-safe access
cacheTTL            time.Duration       // Cache TTL (30 seconds)
```

**Refactored BuildSystemPrompt():**
- Renamed internal build logic to `buildSystemPromptContent()`
- New `BuildSystemPrompt()` checks cache freshness before building
- Only rebuilds if cache has expired (30-second TTL)
- Uses RWMutex for efficient concurrent reads

**Efficiency Gain:**
- First message: System prompt built once → ~3000+ tokens
- Messages within 30 seconds: Cached system prompt reused → 0 additional tokens
- After 30 seconds: Cache expires and rebuilds (typically unchanged content)

### 2. Fixed ForceCompression Logic (pkg/agent/loop.go)

**Before (Broken):**
```go
// Assumed history[0] is system prompt (false assumption)
enhancedSystemPrompt := history[0]
enhancedSystemPrompt.Content = enhancedSystemPrompt.Content + compressionNote
newHistory = append(newHistory, enhancedSystemPrompt)
// ... Result: First message corrupted, system prompt changed
```

**After (Fixed):**
```go
// Simply keep the last 50% of messages
numToKeep := (len(history) + 1) / 2
newHistory := history[len(history)-numToKeep:]
// Result: Conversation history reduced, system prompt unchanged
```

**Benefits:**
- No accidental modification of conversation messages
- No "Emergency compression" notes appearing in wrong places
- System prompt remains consistently generated by cache
- Session history stays clean and correct

### 3. Cache Invalidation Method

Added `InvalidateSystemPromptCache()` method for future use:
- Can be called when memory files are updated
- Can be called when skills are reloaded
- Ensures fresh system prompt when content actually changes

## Performance Impact

### Before Fix
- Every message causes full system prompt rebuild
- System prompt reprocessed with every turn
- Compression corrupts history, leading to undefined behavior

**Example for 5 messages in 30 seconds:**
- Message 1: Build system prompt (~3000 tokens)
- Message 2: Rebuild system prompt (~3000 tokens) + reprocess
- Message 3: Rebuild system prompt (~3000 tokens) + reprocess
- Message 4: Rebuild system prompt (~3000 tokens) + reprocess
- Message 5: Rebuild system prompt (~3000 tokens) + reprocess
- **Total unnecessary reprocessing: ~12,000 tokens**

### After Fix
- First message in 30-second window: Build system prompt (~3000 tokens)
- Message 2-5: Use cached system prompt (reuse, no reprocessing)
- After 30 seconds: Cache expires, rebuild only if needed
- **Total unnecessary reprocessing: ~0 tokens (within the window)**

## Backward Compatibility

All changes are backward compatible:
- Cache is transparent to existing code
- `BuildSystemPrompt()` still returns the same result
- Cache invalidation is optional
- Default 30-second TTL is reasonable for most use cases
